# 外挂监管种子 · 设计规格（工具包 v1.0）

## §0 结论先行

1. **形态**：scaffold（可安装套件）。核心规则也能以 Agent 模式运行，两种形态兼得。
2. **跨平台做法**：核心用**平台无关格式**（JSON 规则集 + 零依赖参考中间件），各平台可用自己的语言实现同一判定逻辑，**不绑定任何单一宿主机制**。
3. **三档控制**：`observe(L-0)`、`suggest(L-1)` **默认开启、安装即生效**；`stop(L-2)` **默认关闭，由安装者开关注明**。开关打开 = 部署者声明已获制止授权。
4. **统一内核**：判定逻辑只有一份（`kernel/engine.py` 的 `evaluate`），四平台接入层只是搬运 verdict——这是第十三轮「统一内核」拍板的结构落点。

## §1 用户给定约束
| 约束 | 落点 |
|---|---|
| 跨平台可安装 | 平台无关核心 + 多平台接入指南 |
| 观察/建议直接执行 | `enforcement.observe/suggest = true`（默认） |
| 制止设开关 | `enforcement.stop = false`（默认），安装者改 `true` |

## §2 四元组
- **E 要素**：`rules.json`（规则核心）、`engine.py`（统一内核）、`cli.py`（参考中间件）、`adapters/`（接入层）、`install.py`（安装器）、`enforcement` 开关。
- **R 关系**：工具调用 → **必经 `evaluate`** → 输出 `verdict` → 平台按档位动作（observe 记录 / suggest 告警 / stop 拦截）。
- **G 规则**：三档默认由 `enforcement` 定；`stop=true` 须 `authorization` 四要素完整 **且** 规则完整性 `integrity=ok`（签名校验通过）；命中高危且 `stop=off`（或签名不符 / 授权缺项）时**降级为 `suggest`**（不伪成功、不静默放行、不越权制止）。
- **B 边界**：① 不进被监管 agent 本体（外挂）；② 不持有被监管者凭据；③ 不改被监管者生产逻辑；④ 只取对外监管最小规则子集，不外溢全量诊断/案例资产。

## §3 三档控制与开关
| 档 | 默认 | 动作 | 责任 | 开启 |
|---|:-:|---|---|---|
| L-0 观察 | on | 记录越界并上报 | 最低 | 安装即生效（仍需授权） |
| L-1 建议 | on | 告警，由被监管方/人工决定 | 中 | 安装即生效（仍需授权） |
| L-2 制止 | off | 直接 block/deny | 最高 | 安装者改 `stop=true` 并填 `authorization` |

## §4 统一内核架构
```
[平台无关核心]
  rules.json      ← 判定规则 + 三档默认 + 授权字段（任何平台可读）
  engine.py       ← 唯一判定入口 evaluate()（零依赖，可移植）
  cli.py          ← 参考中间件（stdin 工具调用 → verdict）
        │
        ├─ WorkBuddy         → PreToolUse hook 调 cli（stop 需 hook 有 deny 权）
        ├─ DeepSeek 生态      → dsh pre-execute 插件调同一内核
        ├─ 通用 API 场景      → 模型输出→执行工具 之间插中间件
        └─ 混元 / Cube        → 环境级网络策略兜底（模型想绕也绕不过）
```
⇒ 统一内核、分平台适配；避免各平台各写一份判定（重复且易漂移）。

## §5 诚实边界
1. 本包是设计 + 最小可运行内核，未在四平台全实测；dsh / 混元 seam 来自文档，未本机验证。
2. observe/suggest 默认开 ≠ 免授权（可监管性 = 有授权 × 有 seam）。
3. `stop` 开关是授权声明，不是授权来源；打开前部署者须确已获制止授权。
4. 只取对外监管最小子集，不含全量方法论。

## §7 安全加固（按外部反馈 P0/P1 落地）

针对「投喂后反馈」指出的四类风险，已把可代码补的缺口闭环：

| 等级 | 项 | 落点 |
|---|---|---|
| P0 | 防篡改闭环 | `install.py` 登记 `kernel/.rules.sig`；`engine.load_rules` 比对 sha256，不符→`integrity=tampered`，`stop` 强制降级为 `suggest` + 告警 |
| P0 | 授权真伪 | `stop` 生效前置 `authorization` 四要素（`granted_by/scope/signed_at/confirmation_token`）结构化校验，缺项即降级；声明 ≠ 验证 |
| P1 | 调用归一化 | `engine._normalize` 做 NFKC + Base64 解码尝试 + leet 折叠（`d15abl3`→`disable`），降低文本变形绕过率 |
| P1 | seam 自检 | `install.py` 按平台打印 seam 确认清单，任一项不满足则 `stop` 不可用 |

**创造级（原需授权）**：宿主不可篡改隔离（容器只读挂载 rules.json / 平台级权限隔离）与环境级行为检测（seccomp / 网络出口策略）属「改造运行环境/平台」，触碰创造级需授权纪律（创造归人）。部署者已授予实施授权；本专家产出**可部署 IaC 产物**（`deploy/`），由部署者在其真实环境落地——本专家保留问询权，不替部署者决定具体网段/节点。

## §8 创造级落地 · 企业级不可篡改稳定性层

授权已给，目标是让**监管自身不可被改写、越界行为在环境层被拦死**（企业级「稳」）。

| 机制 | 类型 | 落点 |
|---|---|---|
| 只读根 fs + rules 只读挂载 / ConfigMap ro | 环境·预防 | Dockerfile / compose `read_only` / k8s `readOnlyRootFilesystem` |
| 非 root + drop ALL capabilities + no-new-privileges | 环境·预防 | compose `security_opt` / k8s `securityContext` |
| seccomp 拦截沙盒逃逸/提权 syscall | 环境·检测 | `deploy/seccomp/profile.json` |
| 网络出口默认拒绝 + 白名单 | 环境·检测 | `deploy/k8s/networkpolicy.yaml` |
| 企业级微服务（stop→403 硬阻断） | 服务化 | `deploy/guard-service.py` |
| `.rules.sig` + 授权四要素 | 内核·检测 | `kernel/engine.py`（P0，兜底） |

**纵深防御**：环境层把「能不能改 / 能不能跑」堵死；内核层把「改了能否生效」兜底；两层任一失效另一层仍在。`install.py` 新增 `enterprise_check`（调用 `kernel/env_lock`）在部署校验时探测 rules 是否真只读，stop 开启却可写即告警。

**逐平台**：Linux 容器/K8s 用 `deploy/` 全量；WB/dsh/混元 沿用各自原生隔离，本层规则只读 + `.rules.sig` 检测作兜底。详见 `ENV_HARDENING.md`。

**诚实边界**：容器/seccomp/eBPF/K8s 需真实 Linux 主机部署，本沙箱跑不了；seccomp 拦截集与网络白名单须按真实业务裁剪；env_lock 检测逻辑已本机验证，环境层本身须部署者验证。
